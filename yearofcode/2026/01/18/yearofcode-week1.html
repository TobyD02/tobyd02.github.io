YOC - Week 1: Finding Motivation

Jan 18, 2026

Slow Beginnings

I wish I could stay the year started off strong – unfortunately, it’s been less productive than I would’ve hoped. Partially due to spending part of the week setting up this blog, but also due to a general lack of motivation. I think I might have overwhelmed myself with the original plan (one completed project every week). This sent me down a path of forcing myself to work every day after work – which just drained my battery of the little charge it had left.

This ended up leading to frustration, but also a dependency on AI slop - unveiling a new goal for the year which is to avoid integrating code into my codebases that I don’t understand. ChatGPT becomes my excuse for laziness - allowing me to solve problems in hacky ways, providing quick results but technical debt longterm. Due to a complete lack of awareness of how a particular component works, you end up depending on AI to add features, fix bugs, etc…

The Project

For my first project of the year, I thought it would be fitting to start off with a “Project Tracker” (or “To-Do” list). I didn’t want it to just be the same old To-Do list on every developer’s GitHub, it needs something different. I decided it would be cool if I could connect my repositories directly to the project tracker, extracting todos directly from the codebase. This would also allow me to track different TODOs on different branches of the same repository. I also thought this would be a good opportunity to learn about Celery, something I’d heard about but never really explored.

There would be two components to this project (though I’d only start on one for this first week):

  1. A backend, Celery oriented, system that runs workers to clone and parse repositories for TODOs - adding (or updating) the records in Postgres.
    • At the moment I have Celery connected to a Redis instance to use for event queues.
  2. A frontend that allows for uploading of repository URLs. This will initiate the first celery task (and subsequently all updating tasks).

Next Steps

Obviously - building the frontend. I’m interested in trying out NiceGUI as an alternative to all the JS/TS frameworks. Also - just extracting TODO’s from a repo isn’t that useful, so i’d like to allow some extra kinds of documentation - having some canvas where you can sketch out architecture diagrams, or throwaway notes, etc… Notes that are useful for the developer but shouldn’t necessarily be in the codebase. These should be scoped, so they can either be viewed in the context of the entire repo, or just a single branch. Also I think it would be cool if each found todo had a hyperlink to the relevant line in the codebase.

I’m undecided as to whether I’ll continue with this project into next week, or whether I’ll move onto something a bit more digestible.
